# ArzanKadeh AI (ارزانکده AI)

یک محل کشف قابل‌اعتماد، زیبا و ساده برای کسب‌وکارهای ایرانی — فروشگاه‌های
اینستاگرامی، تلگرامی، کسب‌وکارهای خانگی، محلی، سالن‌های زیبایی، صنایع
دستی، غذا، خدمات و محصولات.

این یک ربات تلگرام MVP است که به‌صورت **تک‌فایلی** (`bot.py`) با
`aiogram 3.x` و `aiosqlite` نوشته شده است.

## ویژگی‌های پیاده‌سازی‌شده

- دسته‌بندی چندسطحی محصولات با ایموجی مخصوص هر دسته (نه یک دیکشنری سراسری)
  و ناوبری کاملاً مبتنی بر دیتابیس (`parent_id`)
- جستجوی هوشمند محلی و کاملاً رایگان (LocalQueryParser) برای Query های طبیعی فارسی — بدون هیچ API یا سرویس خارجی
- سیستم رشد فروشنده مبتنی بر لینک معرفی اختصاصی (Referral)
- صفحه فروشگاه‌ها و صفحه محصول با وضعیت «تأییدشده 🟢» / «معرفی‌شده ⚪»
- علاقه‌مندی‌ها (❤️)، امتیازدهی و نظرات (⭐)، گزارش تخلف (🚩)
- درخواست مالکیت فروشگاه (Seller Claims)
- ثبت فروشگاه توسط کاربر (وضعیت اولیه: `UNCLAIMED`)
- اعلان‌ها، حساب کاربری و انتخاب شهر
- بخش‌های داغ‌ترین‌ها، جدیدهای امروز، انتخاب ارزانکده، فروشندگان برتر،
  فهرست هدیه — همه بر اساس داده واقعی دیتابیس (بدون آمار ساختگی)
- مقایسه و تبلیغات به‌صورت پیام «به‌زودی» (طبق اسکوپ MVP، بدون قابلیت جعلی)
- ثبت رویدادهای آنالیتیکس (`events`) که هرگز جریان اصلی کاربر را نمی‌شکند
- Fallback handler سراسری برای callbackهای ناشناخته (هیچ دکمه‌ای بی‌پاسخ نمی‌ماند)
- داده نمایشی (Demo) کاملاً اختیاری و به‌وضوح برچسب‌گذاری‌شده (`SEED_DEMO_DATA`)

## نصب و اجرا

```bash
pip install -r requirements.txt
cp .env.example .env
# سپس BOT_TOKEN واقعی را داخل .env قرار بده
python bot.py
```

اگر `BOT_TOKEN` تنظیم نشده باشد، ربات با یک پیام خطای واضح متوقف می‌شود و
کرش نمی‌کند.

## دیتابیس

- `aiosqlite` async، با `PRAGMA foreign_keys = ON`
- جداول: `users, cities, categories, sellers, products, favorites,
  seller_claims, reviews, reports, events, notifications`
- Seed شهرها و دسته‌بندی‌ها **idempotent** است: هربار اجرای مجدد ربات
  رکورد تکراری ایجاد نمی‌کند (چون قبل از seed کردن، تعداد رکوردهای فعلی
  چک می‌شود).
- داده Demo (اختیاری، `SEED_DEMO_DATA=true`) همیشه با پیشوند `DEMO -` /
  `[DEMO]` مشخص می‌شود و هرگز با داده واقعی اشتباه گرفته نمی‌شود.

## جستجوی هوشمند محلی (Local Smart Search)

معماری کاملاً جدا شده طبق الگوی زیر پیاده‌سازی شده است:

```
User Query -> QueryParser -> StructuredQuery -> SearchEngine -> Ranking -> Results
```

- **`QueryParser`**: یک contract ساده (`parse(raw_query) -> StructuredQuery`).
- **`LocalQueryParser`**: تنها پیاده‌سازی فعلی — کاملاً محلی، رایگان، بدون API،
  مبتنی بر regex و دیکشنری. قابلیت‌ها: نرمال‌سازی اعداد فارسی/عربی و حروف
  (ي/ك → ی/ک)، تشخیص قیمت («زیر»، «تا»، «کمتر از»، «بیشتر از»، «بین ... تا ...»،
  واحد میلیون/هزار)، تشخیص شهر و دسته‌بندی از روی همان داده seed شده،
  چند مترادف رایج (گوشی→موبایل، لپ‌تاپ/لپتاپ، ...)، چند غلط تایپی رایج شهر،
  رنگ، جنسیت (با اشکال محاوره‌ای مثل مردونه/زنونه)، و حذف کلمات اضافی
  («می‌خوام»، «یه»، «دنبال»، «برای من»، «تو»/«در»، ...).
- **`SearchEngine`**: فقط با interface بالا کار می‌کند، هیچ وابستگی مستقیمی به
  `LocalQueryParser` ندارد. افزودن `AIQueryParser` در آینده (مثلاً با یک مدل
  هوش مصنوعی) فقط نیازمند پیاده‌سازی همان `parse()` و تغییر یک خط
  (`search_engine = SearchEngine(AIQueryParser())`) است — نه تغییر در
  SearchEngine، Ranking یا هیچ handler ای.
- **Ranking**: ترکیب امتیاز تطابق دسته‌بندی، کلمه کلیدی در نام/توضیحات، شهر،
  محدوده قیمت، امتیاز، تعداد نظر و بازدید — همه از داده واقعی دیتابیس.
- **Fallback سه‌مرحله‌ای**: (۱) جستجوی ساختاریافته کامل → (۲) اگر نتیجه‌ای
  نبود، ساده‌سازی (حذف قیمت/شهر، حفظ کلمه کلیدی/دسته) → (۳) اگر باز هم
  نتیجه‌ای نبود، بازگشت کامل به همان جستجوی LIKE اصلی و بدون تغییر. هیچ
  محصولی جعل نمی‌شود؛ همیشه فقط از دیتابیس واقعی خوانده می‌شود.
- برای Query های ساده (یک کلمه، بدون سیگنال ساختاری) مستقیماً همان جستجوی
  LIKE اصلی و بدون سربار اضافه اجرا می‌شود.

## سیستم رشد فروشنده (Referral)

- هر فروشنده پس از ثبت، یک لینک اختصاصی دریافت می‌کند:
  `https://t.me/<bot_username>?start=shop_<seller_id>`
- ورود از طریق این لینک در جدول `referrals` ثبت می‌شود (`UNIQUE(referred_user_id)`
  تضمین می‌کند هر کاربر فقط یک‌بار و برای یک فروشنده معرفی حساب شود — حتی اگر
  بعداً از لینک فروشنده دیگری هم وارد شود).
- بازدید فروشنده از لینک خودش به‌عنوان معرفی حساب نمی‌شود (self-referral).
- آمار معرفی از حساب کاربری («🎁 لینک معرفی فروشگاه من») همیشه قابل مشاهده است.
- ساختار forward-compatible: `referrals` (Referral Event) + ثابت
  `REFERRAL_REWARD_RULES` (Reward Rules: ۵/۲۰/۵۰/۱۰۰ → امتیاز/Boost/Featured/
  فروشنده ویژه) + جدول `referral_rewards` (Reward، از قبل در schema موجود
  ولی هنوز هیچ کدی در آن نمی‌نویسد) — افزودن جوایز واقعی در آینده نیازمند
  migration نیست.



به دلیل نبود دسترسی شبکه در برخی محیط‌ها (از جمله محیطی که این پروژه در
آن توسعه داده شده)، ممکن است نصب `aiogram` و `aiosqlite` امکان‌پذیر
نباشد. پوشه `tests/` طوری نوشته شده که:

- بدون نیاز به `aiogram`/`aiosqlite` قابل اجراست (فقط با کتابخانه استاندارد
  پایتون + `sqlite3` داخلی)،
- منطق SQL/Schema/Seed را با موتور واقعی SQLite تأیید می‌کند،
- توابع کمکی خالص (`format_price`, `parse_int`, `instagram_url`, ...) را
  مستقیماً تست می‌کند،
- ترتیب ثبت handlerها و برخورد `callback_data` را با تحلیل استاتیک سورس
  بررسی می‌کند (مثلاً اینکه fallback عمومی، `/start` را نبلعد).

اجرا:

```bash
python -m unittest discover -s tests -v
# یا در صورت نصب بودن pytest:
pytest tests -v
```

جزئیات کامل اینکه چه چیزی PASS شده و چه چیزی به دلیل نبود dependency در
محیط توسعه اجرا نشده، در گزارش نهایی چت آمده است.

  متصل نیست.
